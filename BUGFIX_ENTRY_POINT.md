# Исправление ошибки "can't open file '/app/main.py'"

## Проблема

Пользователи получали ошибку при запуске своих ботов:
```
/tmp/venv/bin/python: can't open file '/app/main.py': [Errno 2] No such file or directory
```

## Причина

В `agent/main.py` при создании контейнера использовался неправильный путь к директории проекта:

**Было:**
```python
project_dir = f"/data/projects/{project_id}"  # ❌ Путь не существует на хосте
```

Файлы загружались в `/app/data/projects/{project_id}` (через `_get_project_dir`), но при создании контейнера указывался путь `/data/projects/{project_id}`, который не существовал на хосте. В результате volume не монтировался, и контейнер не видел файлы проекта.

## Исправление

### 1. agent/main.py - create_container

**Изменено:**
```python
project_dir = self._get_project_dir(str(project_id))  # ✅ Правильный путь: /app/data/projects/{project_id}
```

Теперь используется метод `_get_project_dir`, который возвращает правильный путь `/app/data/projects/{project_id}`, куда фактически загружаются файлы.

### 2. Добавлено логирование

Для упрощения диагностики добавлено логирование в:

- **agent/main.py** → `upload_project`: логирует список извлеченных файлов
- **agent/main.py** → `create_container`: логирует параметры создания контейнера
- **services/docker_manager.py** → `create_container`: логирует монтирование volume и команду запуска

## Как это работает

1. **Загрузка файлов** (upload_project):
   - ZIP загружается в `/app/data/projects/{project_id}/`
   - Извлекается в ту же директорию
   - Логируется список файлов

2. **Создание контейнера** (create_container):
   - Получается правильный путь через `_get_project_dir(project_id)`
   - Volume монтируется: `host:/app/data/projects/{project_id}` → `container:/app`
   - Entry point разрешается относительно `/app` внутри контейнера

3. **Запуск**:
   - Контейнер видит все файлы проекта в `/app`
   - Python может найти `main.py` или другой entry point

## Тестирование

После применения исправлений:

1. Загрузите проект через бота
2. Запустите проект
3. Проверьте логи агента - должны появиться записи о монтировании volume
4. Контейнер должен успешно запуститься и найти entry point

## Дополнительные улучшения

Код уже содержит продвинутую логику разрешения entry point в `services/project.py`:

- `_resolve_script_entry` - ищет скрипт в корне или внутри единственной подпапки
- `_resolve_module_env` - настраивает PYTHONPATH для модулей
- При ошибке показывает список доступных .py файлов для диагностики

Это исправление решает проблему на уровне монтирования volume, что является критичным для работы всей системы.

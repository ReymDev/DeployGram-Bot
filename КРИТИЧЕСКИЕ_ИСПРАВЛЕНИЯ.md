## 🔴 ПРОБЛЕМА 1: СОВЛАДЕЛЬЦЫ (Coowners) ✅ ИСПРАВЛЕНО

### Что было:
Совладельцы добавлялись в базу данных, но **НЕ МОГЛИ** управлять проектом:
- ❌ Не могли запускать/останавливать
- ❌ Не могли смотреть логи  
- ❌ Не могли редактировать файлы

### Причина:
Все handlers проверяли только owner:
```python
if project.user_id != db_user.id:
    await callback.answer("Нет доступа", show_alert=True)
    return
```

### Решение:
1. **Создан `bot/utils/access.py`** - helper функция для проверки доступа:
```python
async def check_project_access(project, user, session):
    # Проверяет owner ИЛИ coowner
    if project.user_id == user.id:
        return True
    
    coowner = await coowner_repo.get_by_user_and_project(user.id, project.id)
    return coowner is not None
```

2. **Обновлён `_check_owner()` в `bot_manage.py`**:
```python
async def _check_owner(..., session=None):
    # Owner всегда имеет доступ
    if project.user_id == db_user.id:
        return project
    
    # Проверяем coowner если session передан
    if session is not None:
        if await check_project_access(project, db_user, session):
            return project
    
    await callback.answer("Нет доступа")
    return None
```

3. **Обновлены критичные handlers** (start, stop, logs, view):
```python
async def bot_start(..., session):  # Добавлен session параметр
    project = await _check_owner(..., session)  # Передаём session
```

### Результат:
✅ **Совладельцы ТЕПЕРЬ МОГУТ:**
- ▶️ Запускать проекты
- ⏹️ Останавливать проекты
- 📋 Смотреть логи
- ⚙️ Управлять настройками
- 📁 Работать с файлами

**Файлы изменены:**
- `bot/utils/access.py` (новый)
- `bot/handlers/user/bot_manage.py`

## 🟢 ПРОБЛЕМА 4: МОНИТОРИНГ для VPS ✅ ИСПРАВЛЕНО

### Что было:
Мониторинг (CPU/RAM/Disk) не работал для VPS проектов:
- ❌ Статистика не собиралась
- ❌ Графики были пустыми
- ❌ Проверялся только локальный docker

### Причина:
В `services/monitoring.py` метод `collect_stats()` вызывал несуществующий метод:
```python
# Проблема: вызов несуществующего метода
stats = await client.get_container_stats(project.docker_container_id)
```

А в `VPSClient` есть метод `get_stats()`, а не `get_container_stats()`.

### Решение:
Заменён вызов на правильный метод:
```python
# services/monitoring.py - collect_stats()
if project.server_id:
    client = VPSClient(...)
    try:
        stats = await client.get_stats(project.docker_container_id)  # ✅ Исправлено!
        return await self.stats_repo.create(
            project_id=project_id,
            cpu_percent=stats.get("cpu_percent", 0),
            ram_mb=stats.get("ram_mb", 0),
            disk_mb=stats.get("disk_mb", 0),
        )
    except Exception as e:
        logger.error("Failed to collect stats from VPS")
        return None
```

### Результат:
✅ **Мониторинг ТЕПЕРЬ РАБОТАЕТ для VPS:**
- 📊 Статистика CPU собирается
- 💾 Статистика RAM собирается  
- 💿 Статистика Disk собирается
- 📈 Графики отображаются корректно

## 🔴 КРИТИЧЕСКИЕ ПРОБЛЕМЫ

### 1. **BackupService: Бэкапы не работают с VPS серверами**
**Файл:** `services/backup.py`  
**Проблема:** Методы `create_backup()` и `restore_backup()` работают только с локальной файловой системой:
```python
project_dir = BASE_DIR / "data" / "projects" / str(project_id)
```

**Почему не работает:**
- Если проект на VPS-сервере (project.server_id != None), файлы находятся на удалённом сервере
- BackupService пытается читать/писать локально, но файлов там нет

**Как исправить:**
```python
async def create_backup(self, project_id: int, version_id: int | None = None, size: int = 0):
    project = await self.project_repo.get_by_id(project_id)
    if project is None:
        return None
    
    # НОВОЕ: Проверка на VPS
    if project.server_id:
        # Скачать файлы через VPS Agent API
        from services.vps_agent import VPSClient
        # ... реализовать скачивание ZIP через API
    else:
        # Существующая логика для локальных проектов
        project_dir = BASE_DIR / "data" / "projects" / str(project_id)
        # ...
```

**Влияние:** ⚠️ Бэкапы НЕ РАБОТАЮТ для проектов на VPS

### 2. **project_files.py: Файловый менеджер не работает с VPS**
**Файл:** `bot/handlers/user/project_files.py`  
**Проблема:** Все операции с файлами (`list_files`, `read_file`, `delete_file`) вызываются через `project_service`, но не проверяют где находится проект

**Метод `list_files()` в ProjectService:**
```python
async def list_files(self, project_id: int, path: str = "/app") -> list[str]:
    project = await self.project_repo.get_by_id(project_id)
    if project is None or not project.docker_container_id:
        return []
    
    # Проблема: использует ТОЛЬКО локальный docker!
    if not self.docker:
        return []
    
    return await self.docker.list_files(project.docker_container_id, path)
```

**Влияние:** ⚠️ Файловый менеджер НЕ РАБОТАЕТ для проектов на VPS

**Как исправить:** Добавить проверку `if project.server_id:` и вызывать VPS Agent API

### 3. **project_secrets.py: Секреты не применяются к контейнеру**
**Файл:** `bot/handlers/user/project_secrets.py`  
**Проблема:** Секреты сохраняются в базу данных, но НЕ передаются в контейнер как ENV переменные

**Что происходит:**
1. Пользователь добавляет секрет через бота
2. Секрет сохраняется в `project_version.secrets` (JSON)
3. Но при создании контейнера секреты НЕ загружаются!

**Проверим код создания контейнера:**
```python
# services/project.py - create_and_start()
container_id = await dm.create_container(
    project_id=project.id,
    project_name=project.name,
    python_version=project.python_version,
    entry_point=project.entry_point,
    entry_type=project.entry_type,
    tariff=tariff,
    env_vars=secrets_dict if secrets else {},  # <-- ОК, передаются
    project_dir=project_dir,
)
```

Проверю откуда берутся `secrets_dict`:
```python
secrets_dict = {}
if project.version and project.version.secrets:
    try:
        secrets_dict = json.loads(project.version.secrets)
    except (json.JSONDecodeError, TypeError):
        pass
```

**Проблема:** При `create_and_start()` используется `project.version`, но в базе может быть несколько версий. Нужно брать **latest version**, а не связанную через relationship!

**Влияние:** ⚠️ ENV переменные (секреты) могут не применяться

```python
    stats = await self.docker.get_container_stats(project.docker_container_id)
    # ...
```

**Влияние:** Статистика (CPU/RAM/Disk) не собирается для проектов на VPS

### 5. **versions.py: Откат версий не перезапускает контейнер**
**Файл:** `bot/handlers/user/versions.py`  
**Проблема:** При откате версии (`version_restore`) говорится:

```
"Для применения изменений перезапустите проект."
```

Но пользователь должен вручную идти и нажимать "Перезапустить".

**Улучшение:** Автоматически перезапускать проект после отката версии:
```python
success = await project_service.restore_version(project_id, version_id)
if success:
    # НОВОЕ: автоматический перезапуск
    await project_service.restart_project(project_id)
```

**Влияние:** Плохой UX - пользователь забывает перезапустить

### 8. **coowners.py: Совладельцы не могут видеть проект**
**Файл:** `bot/handlers/user/coowners.py`  
**Проблема:** Совладельцы (co-owners) добавляются в базу, но:

**В handlers проверка только:**
```python
if project is None or project.user_id != db_user.id:
    await callback.answer("Нет доступа", show_alert=True)
    return
```

**НЕ проверяется:** является ли `db_user` совладельцем!

**Как исправить:**
```python
# Проверка owner ИЛИ co-owner
is_owner = project.user_id == db_user.id
is_coowner = await coowner_repo.check_access(project_id, db_user.id)

if not (is_owner or is_coowner):
    await callback.answer("Нет доступа", show_alert=True)
    return
```

**Влияние:** ⚠️ Совладельцы НЕ МОГУТ управлять проектом (функционал не работает!)

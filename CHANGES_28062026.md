# Изменения от 28.06.2026

## ✅ Задача 1: Проверки разрешений совладельцев

### Что сделано:
Добавлены проверки разрешений (`can_start_stop`, `can_view_logs`, `can_edit_files`, `can_manage_deps`, `can_view_settings`) во все хендлеры проектов.

### Изменённые файлы:

#### 1. `bot/utils/access.py`
- Добавлена функция `check_permission()` для проверки конкретных разрешений совладельцев
- Возвращает кортеж `(has_permission, coowner_object)`
- Владелец всегда имеет все права
- Совладельцы проверяются по конкретным полям разрешений

#### 2. `bot/handlers/user/bot_manage.py`
Обновлены хендлеры с проверками разрешений:

- **`bot_start_`, `bot_stop_`** → проверяют `can_start_stop`
- **`bot_logs_`, `logs_file_`** → проверяют `can_view_logs`  
- **`bot_libs_`, `lib_add_`, `lib_del_`** → проверяют `can_manage_deps`
- **`bot_settings_`** → проверяет `can_view_settings`

#### 3. `bot/handlers/user/project_files.py`
Обновлены хендлеры файлового менеджера:

- **Просмотр файлов** (`files_browse_`, `fbrowse_nav_`, `file_action_`, `file_download_`) → требуют базового доступа (owner или coowner)
- **Редактирование файлов** (`files_upload_`, `fupload_nav_`, `upload_here_`, `file_delete_`, `file_del_confirm_`) → проверяют `can_edit_files`

#### 4. `bot/handlers/user/project_logs.py`
Обновлены хендлеры логов:

- **`project_logs_`, `logs_view_`, `logs_download_`** → проверяют `can_view_logs`
- **`logs_clear_`** → только владелец может очищать логи

### Логика разрешений:

```python
# Владелец - полный доступ ко всему
if project.user_id == user.id:
    return True

# Совладелец - проверка конкретного разрешения
has_perm, coowner = await check_permission(project, user, session, "can_start_stop")
if not has_perm:
    await callback.answer("⛔ У вас нет прав на запуск/остановку проекта")
```

## ✅ Задача 2: Система уведомлений

### Что сделано:
Полностью реализована система уведомлений о событиях проектов.

### Изменённые файлы:

#### 1. `services/scheduler.py`
Добавлена новая задача `check_resource_alerts()`:

- Проверяет нагрузку CPU и RAM каждые 10 минут
- Отправляет уведомления при превышении порогов:
  - **CPU > 80%** → уведомление о высокой нагрузке
  - **RAM > 400MB** → уведомление о высоком потреблении памяти
- Избегает спама - отправляет уведомление только при первом превышении
- Сбрасывает флаг уведомления когда показатели возвращаются в норму

#### 2. `bot/main.py`
Добавлена задача в scheduler:
```python
scheduler.add_job(scheduler_service.check_resource_alerts, "interval", minutes=10)
```

#### 3. `services/notifications.py`
Проверка настроек пользователя перед отправкой каждого уведомления:

- `notify_container_stopped` - остановка контейнера
- `notify_container_started` - запуск контейнера
- `notify_error` - ошибки запуска
- `notify_high_cpu` - высокая нагрузка CPU
- `notify_high_ram` - высокое потребление RAM
- `notify_low_disk` - мало места на диске
- `notify_backup_created` - создан бэкап
- `notify_update_done` - обновление выполнено

### Как работают уведомления:

1. **Мониторинг ресурсов** - каждые 5 минут собирает статистику CPU/RAM/Disk
2. **Проверка порогов** - каждые 10 минут проверяет превышение лимитов
3. **Отправка уведомлений** - если настройка включена у пользователя, отправляет уведомление
4. **Предотвращение спама** - флаги `_notified_high_cpu` и `_notified_high_ram` предотвращают повторные уведомления

### Настройки уведомлений:

Пользователь может включить/выключить каждый тип уведомлений в `Профиль` → `⚙️ Настройки` → `🔔 Уведомления`
